# Volento — развёртывание

Интернет-магазин женских классических брюк. Бэкенд Medusa v2, витрина Next.js.

## Что где живёт

| Что | Где |
|---|---|
| Код | `/home/volento/volento` на сервере |
| Бэкенд Medusa | `apps/backend` |
| Витрина Next.js | `apps/storefront` |
| Секреты бэкенда | `apps/backend/.env` (права 600, в git не попадает) |
| Секреты витрины | `apps/storefront/.env.local` (права 600, в git не попадает) |
| Пароли БД и админки | `/root/.volento-secrets` (только для root) |

Адреса: витрина — `https://slytn.ru`, API — `https://api.slytn.ru`, админка — `https://admin.slytn.ru`.

Админка намеренно отключена на `api.slytn.ru` (там `/app` отдаёт 404): у неё отдельное имя. Оба имени ведут в один и тот же процесс на порту 9000.

## Сервисы

Все три поднимаются автоматически после перезагрузки сервера.

```bash
systemctl status medusa-server       # API + админка, порт 9000
systemctl status medusa-worker       # фоновые задачи, порт 9001
systemctl status volento-storefront  # витрина, порт 8000
```

Логи:

```bash
journalctl -u medusa-server -f
journalctl -u volento-storefront -f
```

Все три слушают только `127.0.0.1` — наружу их выпускает исключительно nginx.

## Обновление кода

```bash
cd /home/volento/volento
sudo -u volento git pull

# если менялся бэкенд
cd apps/backend
sudo -u volento env NODE_ENV=production NODE_OPTIONS=--max-old-space-size=3072 npx medusa build
cd .medusa/server && sudo -u volento npm install
systemctl restart medusa-server medusa-worker

# если менялась витрина
cd /home/volento/volento/apps/storefront
sudo -u volento npm install
sudo -u volento env NODE_ENV=production NODE_OPTIONS=--max-old-space-size=3072 npm run build
systemctl restart volento-storefront
```

`NODE_OPTIONS=--max-old-space-size=3072` обязателен: на 2 ГБ памяти сборка без него падает с нехваткой памяти. Работает за счёт файла подкачки на 4 ГБ.

## Фотографии товаров

Лежат в `/var/lib/volento/uploads`, отдаёт их nginx по адресу `https://api.slytn.ru/static/...`.

Два места, где легко наступить на грабли:

**Папку нельзя переносить внутрь проекта.** Medusa по умолчанию складывает загрузки в `.medusa/server/static`, а эту папку команда сборки удаляет целиком — все снимки товаров пропали бы при первом же обновлении кода. Путь задаётся переменной `UPLOAD_DIR`.

**Папку нельзя держать в домашнем каталоге пользователя.** `/home/volento` закрыт правами `750`, nginx туда не зайдёт и отдаст 403. Поэтому `/var/lib/volento`.

При добавлении нового домена его нужно прописать в `apps/storefront/next.config.js` в `images.remotePatterns`, иначе Next откажется показывать картинки.

## Оформление сайта

Картинки и надписи главной правятся на своей странице админки: пункт **«Главная»** в левом меню. У каждого места своя подпись, нужный размер и кнопка загрузки — считать порядок картинок больше не нужно.

Как это устроено: страница живёт в `apps/backend/src/admin/routes/glavnaya`, а хранится всё в метаданных служебной записи «Оформление сайта» (адрес `home-banner`, метка `system`). Medusa не умеет хранить произвольные картинки сайта, зато умеет метаданные и загрузки; из каталога такие записи спрятаны фильтром в `listProducts`, своей страницы у них нет — она отдаёт 404. Витрина читает ключи через `apps/storefront/src/lib/data/home-banner.ts`.

**Ключи картинок:**

| Ключ | Где показывается | Размер |
|---|---|---|
| `верх_телефон` | верхний баннер, телефон | 1080×1350, 4:5 |
| `верх_компьютер` | верхний баннер, компьютер | 2560×1600, 8:5 |
| `середина` | между разделами и низом | 1600×1600, квадрат |
| `низ_телефон` | нижний баннер, телефон | 1080×1350, 4:5 |
| `низ_компьютер` | нижний баннер, компьютер | 2560×1440, 16:9 |
| `плитка_<адрес раздела>` | плитка раздела на главной | 1200×1800, 2:3 |

**Ключи надписей:** `надпись`, `ссылка_текст`, `ссылка_адрес` — текст поверх верхнего баннера; `акция_текст`, `акция_показывать` — полоса над шапкой.

Без нижних картинок внизу повторяется верхний баннер. Плитка раздела без своей картинки берёт фото товара из этого раздела, а если товаров нет — раздел на главной не показывается.

Формат JPEG или WebP, вес до 500 КБ. Картинки обрезаются по центру, если пропорции файла не совпадают с указанными: значимое держать в средней части кадра. Текст в картинку вшивать не нужно — он задаётся ключами и рисуется настоящими буквами.

Раньше место картинки задавалось её номером в блоке «Медиа»: шестая — плитка первого раздела, седьмая — второго. Считать порядок было мучением, поэтому перешли на ключи; перенос старых картинок делает `scripts/setup-banner.js` — он заполняет пустые ключи из первых пяти картинок и не трогает уже выбранное.

Шапка на компьютере — ряд разделов слева, логотип по центру, значки справа (`modules/layout/components/desktop-menu`). У пункта «Каталог» раскрывается панель во всю ширину: колонки ссылок и снимок справа (ключ `середина`). Панель закрывается с задержкой в 0,12 с, иначе схлопывалась бы, пока курсор идёт от кнопки к ней. Наведение на «Новинки» и «Скидки» её закрывает. Выезжающая шторка и поиск слева остались только на телефоне. Шторка на телефоне — белая во весь экран, в два уровня, как на референсе (`modules/layout/components/side-menu`): первый уровень — разделы каталога строкой со стрелкой, у раздела с подразделами стрелка уводит внутрь, у раздела без них ведёт сразу в него. Второй уровень открывается на том же месте, назад — стрелка у заголовка. Ниже снимок со ссылкой на новинки, а кабинет, корзина и выбор языка — в самом низу и мельче: они нужны реже, чем каталог, ради которого меню и открывают.

Ссылок на несуществующие страницы в меню нет: как появятся «о бренде», «доставка», «возврат» — добавить их третьей колонкой в `templates/nav`.

Пункт «Скидки» ведёт в коллекцию `skidki` — она заведена в админке (**Товары → Коллекции → Скидки**) и пока пуста. Товар попадает туда галочкой в его карточке.

Полоса с акцией на компьютере уезжает вверх, как только страницу прокрутили, и возвращается при подъёме к самому верху (`modules/layout/components/promo-bar`); на телефоне остаётся на месте. Ширина, с которой считаем «компьютер», — 1024 px. Положение пересчитывается раз на кадр, а не на каждое событие прокрутки. Пороги разные — прячем после 48 px, показываем ниже 12: с одним общим полоса мигала бы, стоя ровно на нём. Начальное состояние не вычисляется: браузер восстанавливает прокрутку при обновлении страницы уже после запуска этого кода, из-за чего полоса пропадала сразу при заходе.

Блоки главной появляются при прокрутке: `modules/common/components/reveal` — всплывают на 24 px и проявляются за 0,7 с, каждый по разу. Первый экран не анимируется, он и так виден. При системной настройке «уменьшить движение» анимация выключается целиком.

Если запись удалить, витрина покажет запасные файлы из `apps/storefront/public/`.

## Карточка товара

На телефоне всё идёт сверху вниз: хлебные крошки, листалка фотографий, название, цена, описание, цвет, размеры, кнопка. Снимок в листалке занимает 92 % ширины — край следующего выглядывает справа, чтобы было видно, что фото не одно.

На компьютере два столбца: слева фотографии столбцом, справа сведения, прилипшие к верху — кнопка «в корзину» остаётся на виду, пока листаешь снимки. Раньше столбца было три (сведения слева, фото в середине, кнопки справа), и читать приходилось зигзагом.

Кадр 2:3 — тот же, что в карточках каталога, чтобы товар не «прыгал» при переходе из списка.

Под кнопкой «В корзину» стоит «Купить сейчас» — та же покупка, только без остановки в корзине: вещь кладётся и покупатель сразу попадает к оформлению. На телефоне кнопки встают друг под друга, в строку не помещаются.

Размеры набраны текстом в строку, выбранный подчёркнут: рамки вокруг каждого делали из простого ряда цифр подобие клавиатуры. Рост остался вертикальной мерой с засечками.

Чего в карточке нет, хотя есть у референса: ссылки «таблица размеров» и строчки про бесплатную доставку. Первой нет страницы, вторая — обещание, а условия доставки ещё не решены. Появятся — добавим.

Цена стоит под названием, а не в блоке с размерами: покупатель видит её сразу, до всяких выборов. Если размеры товара стоят по-разному, к цене добавляется «от», а точная цена выбранного размера показывается ещё раз рядом с кнопкой. Когда цены одинаковы — а так обычно и есть — второго показа нет.

## Резервное копирование

Каждую ночь в 03:30 UTC снимаются копии базы (хранятся 14 дней) и фотографий товаров (последние 3 архива) в `/var/backups/volento/`. Фотографии копируются отдельно не зря: в дампе базы лежат только ссылки на файлы, и без архива снимков восстановленный магазин будет с пустыми карточками.

```bash
systemctl list-timers volento-backup    # когда следующий запуск
/usr/local/bin/volento-backup.sh        # снять копию прямо сейчас
ls -lh /var/backups/volento/            # что уже есть
```

Восстановление из копии:

```bash
. /root/.volento-secrets
sudo -u postgres createdb -O volento volento_restore
gunzip -c /var/backups/volento/volento_ГГГГ-ММ-ДД_ЧЧ-ММ.sql.gz \
  | PGPASSWORD="$DB_PASSWORD" psql -h 127.0.0.1 -U volento -d volento_restore
```

Восстанавливать сначала в отдельную базу, посмотреть, что данные на месте, и только потом заменять рабочую. Проверка восстановления делалась — дамп разворачивается полностью.

## Шрифты

Лежат в `apps/storefront/public/fonts/` и подключены в `src/styles/fonts.css` — с Google не тянутся: внешняя зависимость один раз уже уронила сборку, да и покупателям незачем ходить на чужие домены.

Сейчас весь сайт набран **Jost** — геометрический гротеск. Рядом лежат и подключены ещё два комплекта — **Tenor Sans** и **Lora** (антиква с засечками): примерить любой — это убрать лишние имена из двух переменных в `globals.css`, заново качать ничего не надо. Все под SIL OFL, копии лицензий рядом с файлами.

Важное различие: Jost и Lora переменные, насыщенности в них настоящие — `font-light`, `font-medium`, `font-bold` работают честно. У Tenor Sans начертание одно, поэтому «сделай легче» на нём не даёт ничего, а «сделай жирнее» браузер подделает грубым скачком.

Файл разбит по алфавитам, браузер тянет только нужные куски:

| Файл | Что покрывает | Размер |
|---|---|---|
| `tenor-sans-cyrillic.woff2` | русский | 6 КБ |
| `tenor-sans-latin.woff2` | латиница | 10 КБ |
| `tenor-sans-latin-ext.woff2` | расширенная латиница | 7 КБ |
| `jost-cyrillic.woff2` | русский | 10 КБ |
| `jost-latin.woff2` | латиница | 26 КБ |
| `jost-latin-ext.woff2` | расширенная латиница | 17 КБ |
| `lora-cyrillic.woff2` | русский, запасной комплект | 21 КБ |
| `lora-cyrillic-ext.woff2` | остальная кириллица | 23 КБ |
| `lora-latin.woff2` | латиница | 37 КБ |
| `lora-latin-ext.woff2` | расширенная латиница | 20 КБ |

Неиспользуемый комплект браузер не скачивает: правило `@font-face` тянет файл только когда шрифт реально понадобился.

Роли задаются переменными в `src/styles/globals.css`: `--font-display` (заголовки) и `--font-sans` (текст) — сейчас обе указывают на Jost, следом Tenor Sans и Lora запасными. Размер заголовков главной — в одном месте, `modules/home/components/section-heading`.

Прежние Doloman Pavljenko, Prata и Manrope удалены: они больше нигде не использовались, а мёртвые файлы в раздаче только путают.

## Переменные окружения

`apps/backend/.env` — значения смотреть на сервере, здесь только имена:

```
NODE_ENV, DATABASE_URL, REDIS_URL, EVENTS_REDIS_URL, WE_REDIS_URL, CACHE_REDIS_URL,
JWT_SECRET, COOKIE_SECRET, AUTH_MFA_ENCRYPTION_KEY,
STORE_CORS, ADMIN_CORS, AUTH_CORS
```

Redis разделён по базам: `/0` сессии, `/1` события, `/2` движок процессов, `/3` кеш.

`WORKER_MODE` и `ADMIN_DISABLED` в `.env` не задаются — их выставляют systemd-юниты, чтобы один и тот же код работал и как сервер, и как воркер.

`apps/storefront/.env.local`:

```
NEXT_PUBLIC_MEDUSA_BACKEND_URL, NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY,
NEXT_PUBLIC_BASE_URL, NEXT_PUBLIC_DEFAULT_REGION
```

Все переменные витрины с приставкой `NEXT_PUBLIC_` попадают в код, который выполняется в браузере покупателя. Поэтому `NEXT_PUBLIC_MEDUSA_BACKEND_URL` — это публичный адрес `https://api.slytn.ru`, а не внутренний `127.0.0.1:9000`. Секреты в переменные с такой приставкой класть нельзя.

## Структура каталога

Заложена сознательно, менять осторожно:

- **Товар** — модель определённого цвета, со своим артикулом (например, «Брюки классические прямые, чёрный», артикул `VLT-001-BLK`).
- **Вариант** — размер + рост. У каждого свой SKU.
- **SKU** — формат `АРТИКУЛ-РАЗМЕР-РОСТ`, например `VLT-001-BLK-46-170`. Должен совпадать со складским посимвольно: к нему будет привязана синхронизация остатков.
- **Остатки** ведутся на уровне варианта, на складе «Основной склад».
- Регион «Россия», валюта — рубль.

**Почему цвет — отдельный товар, а не опция варианта.** Каталог в Medusa перечисляет товары, а не варианты. Если бы цвет был опцией внутри товара, модель попадала бы в каталог одной карточкой, и показать её же в трёх цветах тремя карточками было бы нельзя. Плюс фотографии в Medusa привязаны к товару, а не к варианту — при переключении цвета снимки не менялись бы. И артикул со склада уже содержит цвет, иначе два цвета одной модели давали бы одинаковый SKU.

**Как цвета связаны между собой.** У каждого товара есть метка `model:<КОД МОДЕЛИ>` и поля `model`, `article`, `color`, `color_hex` в metadata. Компонент `ColorSelect` на витрине находит по метке остальные цвета модели и рисует переключатель.

Метку и поля заполняет импорт из выгрузки, руками их трогать не нужно.

## Импорт каталога из выгрузки склада

Два шага. Первый готовит данные на компьютере, второй заводит их на сервере.

```bash
# 1. из .xlsx получаем catalog.json
python3 scripts/build-catalog.py "data/warehouse/2026-09-02-ostatki.xlsx"

# 2. кладём на сервер и заводим
scp scripts/import-catalog.js scripts/catalog.json volento:/home/volento/
ssh volento 'sudo bash -c "set -a; . /root/.volento-secrets; set +a; cd /home/volento && node import-catalog.js"'
```

Полезные ключи `import-catalog.js`:

- `--limit 2` — только первые два товара, для пробы;
- `--stock` — не трогать товары, обновить одни остатки;
- `--price 5900` — поставить всем одну цену вместо заглушки.

Что делает `build-catalog.py`:

- берёт из выгрузки строки «Женское / Брюки»;
- группирует по артикулу склада: артикул = товар, строки внутри = варианты (размер + рост);
- **выдаёт свои коды** `VLT-0001`, SKU варианта `VLT-0001-46-170`. Складской артикул не годится в SKU: он чужой и может поменяться, поэтому лежит в `metadata.article`, а ключ синхронизации `артикул-размер-рост` — в `metadata.wh_key` каждого варианта;
- берёт номер модели из «Мод. NNN» в названии (он есть у всех строк) и ставит метку `model:NNN` — по ней собирается переключатель цветов;
- **собирает название заново.** В выгрузке названия складские: имена поставщиков («Зара», «Оле Доле», «Elie Saab», «Charmstore»), коды тканей («D#13», «GC8369-9»), номера цветов. Ставить это на витрину нельзя, поэтому название складывается из кроя и ткани: «Брюки палаццо изо льна, бежевый». Исходное имя сохраняется в `metadata.source_name`;
- остаток берёт из колонки «Доступный запас», а не из физического.

Правила разбора — списки `FABRIC` (ткань) и `CUT` (крой) в начале скрипта. Появится новая модель или ткань — дописать туда, иначе название соберётся без этой части.

Импорт **можно запускать повторно**: товар с уже занятым адресом пропускается, остатки обновляются.

**Товары заводятся черновиками.** В выгрузке склада нет колонки с ценой, а Medusa не создаёт вариант совсем без цены. Поэтому ставится заглушка 1 ₽ и `metadata.price_pending = true`. Черновик не виден на витрине и не покупается — продать по 1 ₽ нельзя. Перед публикацией цены нужно проставить.

## Оплата: сертификат Минцифры

Сертификат `tochka.com` выдан корневым центром Минцифры, которого нет в
доверенных ни у macOS, ни у Node. Без него любой запрос к API банка падает
с `SELF_SIGNED_CERT_IN_CHAIN`, а curl отдаёт код 000 — выглядит как «сайт
недоступен», хотя дело в доверии, а не в сети.

Связка лежит в `deploy/certs/tochka-ca.pem` (корневой + промежуточный,
скачаны с gu-st.ru). На сервере она в `/etc/volento/tochka-ca.pem` и
прописана **только нашему бэкенду** — дополнением к юнитам
`medusa-server` и `medusa-worker`:

```
/etc/systemd/system/medusa-server.service.d/tochka-ca.conf
[Service]
Environment=NODE_EXTRA_CA_CERTS=/etc/volento/tochka-ca.pem
```

В общесистемное хранилище не добавляли специально: иначе серверу пришлось
бы доверять этому центру целиком. Откат — удалить два файла-дополнения и
`systemctl daemon-reload`.

Проверка (с сервера, из-под пользователя volento):

```bash
NODE_EXTRA_CA_CERTS=/etc/volento/tochka-ca.pem node -e '
fetch("https://enter.tochka.com/sandbox/v2/open-banking/v1.0/customers",
 {headers:{Authorization:"Bearer sandbox.jwt.token"}}).then(r=>console.log(r.status))'
```

Должно быть 200. Без токена — 403, тоже нормально: значит TLS прошёл.

Промежуточный сертификат истекает в марте 2027 — перевыпустить связку.

## Что настроено на сервере

- Ubuntu 26.04, вход по SSH только по ключу, пароль отключён
- ufw: наружу открыты только 22, 80, 443
- PostgreSQL 18 и Redis 8 слушают только `127.0.0.1`
- Файл подкачки 4 ГБ (`/swapfile`)
- nginx как обратный прокси, HTTPS от Let's Encrypt с автопродлением
- Приложение работает под пользователем `volento` без прав администратора

## Особенности, о которых стоит помнить

**Витрина вне общего пространства зависимостей.** Стартер Medusa рассчитан на pnpm; при установке через npm зависимости «поднимаются» в корень, и Next начинает видеть React 18 от бэкенда вместо React 19. Сборка падает с React error #31. Поэтому `apps/storefront` исключён из `workspaces` в корневом `package.json` и имеет собственный `node_modules`. Не возвращайте его в workspaces без перехода на pnpm.

**Патч в `apps/storefront/src/middleware.ts`.** За обратным прокси Next не доверяет заголовку `Host` и подставляет `localhost:8000`, из-за чего покупатель уезжает на несуществующий адрес. Origin для перенаправления собирается из заголовков `x-forwarded-host` / `host`, которые проставляет nginx. При обновлении стартера патч нужно накатить заново.

**Откуда берётся витрина.** Из официального шаблона `medusajs/dtc-starter` — это тот же монорепозиторий, из которого `create-medusa-app` разворачивает бэкенд. Отдельный репозиторий `medusajs/nextjs-starter-medusa` заархивирован в июле 2026 и больше не обновляется; брать код оттуда не надо.

**Сборка витрины обращается к API по публичному адресу.** `NEXT_PUBLIC_MEDUSA_BACKEND_URL` попадает в браузерный код, поэтому там публичный `https://api.slytn.ru` — и при сборке сервер стучится сам к себе через внешний интерфейс. Такая петля ненадёжна и один раз уронила сборку по таймауту. В `/etc/hosts` на сервере добавлено `127.0.0.1 api.slytn.ru`, чтобы запросы шли сразу на локальный nginx. На браузеры покупателей это не влияет.

**Не пересобирайте витрину одновременно с изменением каталога.** Сборка собирает данные страниц из API; если в этот момент товары пересоздаются, сборка падает.

**Перевод витрины.** Русский текст вписан прямо в компоненты, библиотеки локализации нет — магазин одноязычный, и лишний слой абстракции тут не нужен. Обратная сторона: при обновлении витрины из upstream переводы придётся накладывать заново. Формат цен и дат задаётся локалью `ru-RU` в `src/lib/util/money.ts` и в местах вывода дат.

**Кеш витрины.** Список товаров кешируется Next.js. После изменений в каталоге новые товары появляются не сразу. Немедленно — так:

```bash
rm -rf /home/volento/volento/apps/storefront/.next/cache
systemctl restart volento-storefront
```

## Ещё не сделано

Оплата, доставка, письма, статические страницы (оферта, политика обработки данных, возврат), синхронизация со складом по API.

По каталогу: 308 товаров заведены черновиками, у них **нет цен и нет фотографий**. Чтобы открыть их на витрине, нужно проставить цены (найти по `metadata.price_pending`), загрузить съёмку и перевести в «Опубликован».
