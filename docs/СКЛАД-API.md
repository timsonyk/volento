# Обмен со складом — API Volento

## Как работает синхронизация

**Обновление остатков:** раз в минуту склад заливает актуальные цифры по всем SKU (артикулам типа `3149-46/170`). Число абсолютное — не "+3" или "−1", а "сейчас доступно 5 пар". Пропустили запрос — не страшно, следующий всё выправит.

**Оформление заказа:**
1. Человек добавил в корзину и видит остаток с задержкой до минуты
2. Нажал "Оплатить" — **проверяем прямо сейчас**, мимо кэша:
   - хватает — деньги списываются
   - не хватает — показываем "пока оформляли, разобрали", деньги не берём
3. После оплаты заказ падает в очередь
4. Склад забирает задания, видит все несобранные заказы с адресами и составом
5. Склад отвечает "собираю" — или "отказ", тогда возвращаем деньги
6. Собрал — шлёт "собрано" и коды Честного знака по каждой штуке
7. Мы создаём отправление в службе (Яндекс, СДЭК), служба выдаёт наклейку
8. Заказ появляется в списке "к упаковке" со ссылкой на наклейку. Склад печатает, клеит и отмечает "упаковано"
9. В пункте выдачи покупатель меряет и забирает только то, что подошло. Остальное служба везёт обратно
10. Что едет обратно — в списке "возвраты" с кодами каждой пары. Приняли посылку — шлёте коды пришедших пар
11. Покупатель может вернуть забранное в течение 7 дней — оформляет в личном кабинете. Такие возвраты тоже в списке "возвраты"

**Отказы редки:** проверка перед оплатой их отсекает. Отказ нужен только если в те же секунды, что шла оплата, ту же пару купили на другой площадке.

## Подключение

База: `https://api.slytn.ru`

Ключ выдаётся отдельно, прописать один раз в код.

Передавать в заголовке `X-Sklad-Key` на каждом запросе.

Ошибки: `400` — что-то не так в запросе (в ответе написано, что именно),
`401` — ключ неверный, `403` — адрес не в списке, `404` — нет такого
заказа, `409` — действие сейчас невозможно (заказ отменён, наклейки ещё
нет и т. п.), `500` — наша поломка, повторить через минуту.

Ответы на русском: поле `ошибка` — что случилось, иногда `podskazka` —
что делать.

## Ключ позиции

**Артикул Озона** — тот самый `offer_id` из озоновских поставок:

```
3149-46/170   артикул, размер, рост
5110-38       юбки и рубашки — без роста
5390-38/40    блузы — составной размер «38, 40», роста нет
```

Можно слать целиком (`artikul`) или по частям (`model`, `razmer`,
`rost`) — понимаем оба вида. Баркоды и артикулы ВБ не нужны.

## 1. Залить остатки

```
POST /sklad/ostatki
```

```json
{
  "ostatki": [
    { "artikul": "3149-46/170", "kolichestvo": 4 },
    { "artikul": "5110-38", "kolichestvo": 0 },
    { "model": "3149", "razmer": "48", "rost": "176", "kolichestvo": 12 }
  ]
}
```

Ответ: `{ "prinyato": 1998, "ne_nashli": [ … ] }`. Если какую-то строку
не поняли (нет ни `artikul`, ни трёх частей), она вернётся в
`ne_razobrali`.

**`kolichestvo` — сколько готовы продать прямо сейчас**, за вычетом
отложенного под другие заказы. То же число, что уходит на Озон: там
оно уже посчитано, отдельная логика для нас не нужна.

Число абсолютное, не разница: пропущенный запрос ничего не ломает.
Не больше **2000 позиций** за раз (больше — `400`), весь каталог это
7 запросов, 13 секунд.

`ne_nashli` — чего нет в нашем каталоге. Это нормально, вы торгуете
шире. Но резкий рост списка = артикулы разошлись, обмен остановить.

## 2. Забрать задания

```
GET /sklad/zadaniya
```

Отдаёт всё несобранное. Прислали "собрано" — задание исчезло. Меток
времени помнить не нужно. `vzyato: true` — вы уже ответили "собираю".

```json
{
  "zadaniya": [{
    "nomer": "5",
    "sozdan": "2026-09-27T16:39:42.376Z",
    "vzyato": false,
    "pozicii": [{
      "artikul": "5985-42/170",
      "nazvanie": "Брюки палаццо классические, светло-серый",
      "kolichestvo": 1,
      "id_stroki": "ordli_01M3HVS5H1YA065KWC5F8K5MW6"
    }],
    "dostavka": {
      "sposob": "pvz",
      "perevozchik": "yataxi",
      "punkt": { "id": "2165496", "adres": "142279, МО, Оболенск, пр-т Биологов, 1" },
      "gorod": "Серпухов"
    },
    "poluchatel": { "imya": "Елена Перова", "telefon": "+79001234567" }
  }]
}
```

`sposob`: `pvz` — везти в пункт (адрес в `punkt`), `kurier` — адрес
получателя в `adres`. Сейчас на сайте только пункты выдачи, курьер
появится позже. Заказ приходит оплаченным.

## 3. Взять в работу

```
POST /sklad/zadaniya/{nomer}/vzyat
```

Без тела. Ответ: `{ "sostoyanie": "vzyat" }`. Говорит нам "заказ увидели,
собираем" — иначе через 3 минуты после оплаты у нас срабатывает тревога
"склад молчит". Остаток не трогает. Повтор не ошибка.

## 4. Собрано

```
POST /sklad/zadaniya/{nomer}/sborka
```

```json
{
  "pozicii": [
    { "id_stroki": "ordli_01M3HVS5H1YA065KWC5F8K5MW6", "kolichestvo": 2,
      "kody": ["0104601234567890215Abc…\u001d93dGVz", "0104601234567890215Xyz…\u001d93AbCd"] }
  ]
}
```

- `id_stroki` — из задания (или `artikul` вместо него)
- `kody` — **по коду на каждую штуку**, целиком, как отдаёт сканер:
  `01` + GTIN + `21` + серийный номер, разделитель GS (`\u001d`), `93` и
  криптохвост. Без хвоста касса не пробьёт чек.
- Коды должны быть **введены в оборот** и числиться за продавцом —
  ИП Нарыжных Е. Н., ИНН 507701029413. Касса проверяет каждый код в
  Честном знаке и не продаст пару с чужим или не введённым кодом.

**"Собрано" шлётся один раз на весь заказ** — когда собрали всё, со
всеми кодами сразу. По одной штуке не присылайте: первая же неполная
отправка поставит заказ на паузу как "не хватает товара".

Ответ: `{ "sostoyanie": "v_sborke" }`. Дальше мы сами создаём
отправление в службе — через несколько минут заказ появится в
`/sklad/k-upakovke`.

Повтор не ошибка — придёт `uzhe_v_sborke` (или `zhdem_klienta`, если
заказ на паузе, см. ниже).

**Собрали не всё** (например, 1 из 2) — пришлите только собранное:
у недостающей строки `kolichestvo` меньше или 0, или не присылайте её
вовсе. Коды — только на собранные штуки. Ответ:
`{ "sostoyanie": "zhdem_klienta" }`. Заказ встаёт на паузу и уходит из
заданий: мы звоним покупателю. Согласился на остаток — заказ сам придёт
в `/sklad/k-upakovke` с уже присланными кодами, недостающее верните на
полку. Отказался — заказ отменим, верните на полку всё.

Ошибки `400` — с объяснением: кодов меньше или больше, чем штук; код
не похож на код маркировки; код или строка присланы дважды; ничего не
собрано (это не сборка, а отказ).

### Заказ из двух помещений — несколько пакетов

Если вещи одного заказа лежат в разных помещениях, заказ можно разделить
на пакеты: что собрано в одном помещении — один пакет, в другом — второй.
Вместо `pozicii` пришлите `pakety`:

```
POST /sklad/zadaniya/{nomer}/sborka
```

```json
{
  "pakety": [
    { "sklad": "A", "pozicii": [
      { "artikul": "5985-42/170", "kolichestvo": 1, "kody": ["0104601234567890215aBcDeF..."] }
    ]},
    { "sklad": "B", "pozicii": [
      { "artikul": "5985-42/170", "kolichestvo": 1, "kody": ["0104601234567890215gHiJkL..."] },
      { "artikul": "3147-46/176", "kolichestvo": 1, "kody": ["0104601234567890215mNoPqR..."] }
    ]}
  ]
}
```

- `sklad` — ваша метка помещения, любая строка до 40 знаков («A», «B»,
  «Дегунинская»). Мы её не проверяем, а возвращаем в списке к упаковке.
- Позиции внутри пакета — как в обычной сборке: строка по `id_stroki`
  или `artikul`, количество и коды на каждую штуку.
- Одна строка заказа может лежать в двух пакетах (две одинаковые пары из
  разных помещений): в каждом пакете своя часть и свои коды.
- Пакетов — до 5. Номер пакета — его место в списке: первый, второй.
- Всё в одном помещении — шлите по-старому, `pozicii`. Это то же, что
  один пакет. `pakety` и `pozicii` вместе — ошибка `400`.

Ответ: `{ "sostoyanie": "v_sborke", "paketov": 2 }`.

В службу уходит **одно отправление из стольких мест, сколько пакетов**:
одна доставка, один трек, покупатель получает все пакеты разом в одном
пункте. На каждый пакет служба даёт **свою наклейку** (разделы 6 и 7).
Пакеты сдаются в службу вместе: пакет из второго помещения с уже
наклеенной наклейкой привозите туда, откуда сдаёте посылки.

Заказ в **постамат** делить нельзя: в ячейку кладут одно место. На
`pakety` с двумя пакетами придёт `409` с объяснением — соберите такой
заказ одним пакетом.

## 5. Отказ

```
POST /sklad/zadaniya/{nomer}/otkaz
{ "prichina": "net_na_sklade" }
```

Резерв снимем, деньги вернём, с покупателем свяжемся сами.

**Отказ нужен только для одного случая** — последнюю пару купили
одновременно у нас и на другой площадке. Прямо перед оплатой мы
проверяем остаток заново, поэтому обычная нехватка до вас не доходит.

После "собрано" отказаться нельзя (`409`) — если что-то пошло не так
уже после сборки, напишите нам. После "собираю" — можно. Повтор отказа
не ошибка — придёт `uzhe_otmenen`.

`prichina` можно не присылать.

## 6. К упаковке

```
GET /sklad/k-upakovke
```

```json
{
  "k_upakovke": [{
    "nomer": "5",
    "perevozchik": "yataxi",
    "trek": "LO-123456789",
    "etiketka": "/sklad/zadaniya/5/etiketka",
    "pozicii": [{ "artikul": "5985-42/170", "nazvanie": "Брюки палаццо классические", "kolichestvo": 1 }]
  }],
  "zhdut_etiketku": ["6"]
}
```

`zhdut_etiketku` — собрано, но служба ещё не выдала наклейку (обычно
пара минут). `perevozchik`: `yataxi` — Яндекс, `cdek` — СДЭК.

У каждого заказа есть ещё список `pakety` — что положить в какой пакет:

```json
"pakety": [
  { "nomer": 1, "sklad": "A", "upakovan": false,
    "etiketka": "/sklad/zadaniya/5/etiketka?paket=1",
    "pozicii": [{ "artikul": "5985-42/170", "nazvanie": "Брюки палаццо классические", "kolichestvo": 1, "kody": ["0104601234567890215aBcDeF..."] }] },
  { "nomer": 2, "sklad": "B", "upakovan": false,
    "etiketka": "/sklad/zadaniya/5/etiketka?paket=2",
    "pozicii": [ ... ] }
]
```

Заказ не делили — в `pakety` один пакет со всеми вещами, а его
`etiketka` та же, что у заказа. `pozicii` и `etiketka` самого заказа
остались как были: кто не делит заказы, может `pakety` не читать.

## 7. Наклейка

```
GET /sklad/zadaniya/{nomer}/etiketka
```

PDF службы, с тем же ключом. Размер задан у нас: **75×120** для Яндекса,
**A7 (74×105)** для СДЭК — обе помещаются на ленту 75×120. Пока
наклейки нет — `409`. Заказ не собран или уже упакован — `404`.

Заказ из нескольких пакетов:

```
GET /sklad/zadaniya/{nomer}/etiketka?paket=2
```

— PDF с одной наклейкой, для второго пакета. Без `paket` придёт общий
файл: по странице на пакет, по порядку. Нет такого пакета — `404`.

Если служба вдруг прислала страниц не столько, сколько пакетов, мы не
угадываем: на `?paket=N` придёт общий файл целиком и заголовок
`X-Nakleyka: vse-mesta`. Тогда номер места смотрите на самой наклейке.

## 8. Упаковано

```
POST /sklad/zadaniya/{nomer}/upakovano
```

Без тела. Упаковали, наклеили, отдали на отправку — заказ уходит из
`/sklad/k-upakovke`. Ответ `{ "sostoyanie": "upakovan" }`, повтор —
`uzhe_upakovan`. Без наклейки отметить нельзя (`409`): посылку без неё
служба не примет.

Заказ из нескольких пакетов можно отмечать по одному:

```
POST /sklad/zadaniya/{nomer}/upakovano
{ "paket": 2 }
```

Ответ: `{ "sostoyanie": "paket_upakovan", "paket": 2, "ostalos": [1] }` —
второй пакет упакован и с наклейкой, ждём первый. В `/sklad/k-upakovke`
у этого пакета станет `"upakovan": true`. Когда отмечен последний,
придёт обычное `upakovan` и заказ уйдёт из списка. Без тела — упакованы
все пакеты сразу.

## Упаковка

- Один заказ = одна упаковка = одна наклейка, сколько бы ни было штук.
  Исключение — заказ из двух помещений: тогда пакет на помещение и
  наклейка на каждый пакет (раздел 4)
- Брюки в зип-пакете, сверху курьерский пакет; если штук много — коробка
- Заклеить так, чтобы вскрытие было видно
- Наклейка службы — на внешнюю упаковку, не на товар
- Код ЧЗ — на брюки или зип-пакет, **не на внешнюю упаковку**
- **У каждой пары свой код ЧЗ и ярлык с артикулом и размером.** В пункте
  выдачи покупатель меряет, и сотрудник по ярлыку и коду отмечает, какую
  пару забрали, а какую нет
- **В каждую посылку — памятку о возврате** (файл `pamyatka-vozvrat-75x120.pdf`,
  печатается на той же ленте 75×120). Это требование закона: без неё срок
  возврата у покупателя вырастает с 7 дней до 3 месяцев
- Правила Яндекса: https://yandex.ru/support/delivery-profile/ru/other-day/packing-rules

## Куда сдаём посылки

- Яндекс: Москва, ул. Ивана Сусанина, 6 к1
- СДЭК: Москва, Ильменский пр-д, 17 к2

Какая служба у заказа — поле `perevozchik` в `/sklad/k-upakovke`
(`yataxi` — Яндекс, `cdek` — СДЭК). Посылки разных служб не смешивать.

## Тестовый режим

Проверить свой код целиком, ничего не отправляя на самом деле:

```
POST /sklad/proba/zakaz
{ "kolichestva": [3] }        одна строка, 3 шт.
{ "kolichestva": [2, 1] }     две строки
```

Ответ: `{ "id": "order_…", "nomer": "25" }`. До трёх строк, в каждой от
1 до 10 штук; без тела — одна строка, 1 шт.

Деление на пакеты проверяется на тех же тестовых заказах: соберите
заказ `[2, 1]` с `pakety` — в `/sklad/k-upakovke?test=1` придут два
пакета, а тестовая наклейка будет из двух страниц («PLACE 1 OF 2»,
«PLACE 2 OF 2»). `{ "kolichestva": [1, 1], "postamat": true }` — заказ
«в постамат»: на нём видно отказ `409` при делении.

Тестовые заказы видны **только** с `?test=1`:

```
GET /sklad/zadaniya?test=1
GET /sklad/k-upakovke?test=1
GET /sklad/vozvraty?test=1
```

Выдачу в пункте за службу изображает:

```
POST /sklad/proba/vydacha/{nomer}
{ "vykupleno": [1, 0] }       сколько штук забрали по каждой строке
```

Без тела — забрали всё, `[0, 0]` — не забрали ничего. Только после
"упаковано". Что не забрали, появится в `/sklad/vozvraty?test=1`.

Возврат покупателя за него изображает:

```
POST /sklad/proba/vozvrat/{nomer}
{ "shtuk": 1 }                сколько пар вернуть, без тела — все
```

В обычных списках их нет, и в обычных нет тестовых — можно гонять
сколько угодно. Остальное — как у настоящих: "собираю", "собрано" с
кодами, отказ, неполная сборка, наклейка, "упаковано". Отличия:

- артикулы `TEST-46/170`, `TEST-48/176`, `TEST-50/182` — их нет в вашей базе
- отправление в службу не уходит: `perevozchik: "test"`, трек `TEST-25`
- наклейка — тестовый PDF 75×120 с надписью TEST LABEL: годится проверить
  печать и размер
- коды ЧЗ можно слать выдуманные, но правильного вида
  (`01` + 14 цифр + `21` + серийный номер)

## Цикл

```js
const КЛЮЧ = "sk_sklad_…"
const БАЗА = "https://api.slytn.ru"

const запрос = (путь, настройки = {}) =>
  fetch(БАЗА + путь, {
    ...настройки,
    headers: {
      "Content-Type": "application/json",
      "X-Sklad-Key": КЛЮЧ,
      ...(настройки.headers || {}),
    },
  })

async function круг() {
  const позиции = собратьОстаткиИзСвоейБазы()
  for (let i = 0; i < позиции.length; i += 2000) {
    await запрос("/sklad/ostatki", {
      method: "POST",
      body: JSON.stringify({ ostatki: позиции.slice(i, i + 2000) }),
    })
  }

  const { zadaniya } = await (await запрос("/sklad/zadaniya")).json()

  for (const з of zadaniya) {
    if (!проверитьУСебя(з.pozicii)) {
      await запрос(`/sklad/zadaniya/${з.nomer}/otkaz`, { method: "POST", body: "{}" })
      continue
    }
    if (!з.vzyato) {
      await запрос(`/sklad/zadaniya/${з.nomer}/vzyat`, { method: "POST", body: "{}" })
    }
    // "собрано" с кодами шлёте, когда собрали и наклеили ЧЗ:
    // POST /sklad/zadaniya/{nomer}/sborka { pozicii: [{ id_stroki, kolichestvo, kody }] }
  }

  const { k_upakovke } = await (await запрос("/sklad/k-upakovke")).json()
  for (const о of k_upakovke) {
    // заказ висит в списке, пока не отмечен "упаковано" — печатаем один раз
    if (ужеНапечатано(о.nomer)) continue
    напечатать(await (await запрос(о.etiketka)).arrayBuffer())
    // упаковали и отдали — POST /sklad/zadaniya/{nomer}/upakovano
  }
}

setInterval(круг, 60_000)
```

Лимитов на частоту нет.

## 10. Возвраты: что едет обратно

```
GET /sklad/vozvraty
```

Здесь всё, что должно приехать обратно, пока вы не отметили приём. Два
вида, поле `vid`:

- `nevykup` — в пункте выдачи покупатель примерил и забрал не всё,
  остальное служба везёт обратно;
- `pokupatel` — покупатель забрал заказ, а потом оформил возврат в личном
  кабинете (`zayavka` — номер заявки, например `41-В1`). Он отправляет
  посылку сам; номер заявки вложен в посылку.

```json
{
  "vozvraty": [{
    "nomer": "41",
    "vid": "nevykup",
    "perevozchik": "yataxi",
    "trek": "LO-123456789",
    "kogda_vydan": "2026-10-25T12:00:00.000Z",
    "pozicii": [{
      "artikul": "5986-46/170",
      "nazvanie": "Брюки палаццо классические, капучино",
      "kolichestvo": 1,
      "kody": ["0104601234567890215Abc…\u001d93dGVz"]
    }]
  }]
}
```

`kody` — коды ЧЗ тех пар, которые должны вернуться.

- Невыкуп: деньги покупателю мы уже вернули, пары не проданы — их можно
  продавать снова.
- Возврат покупателя: деньги вернём, когда вы примете посылку. Пары
  проверьте: не носили, ярлыки на месте.

## 11. Возврат принят

```
POST /sklad/zadaniya/{nomer}/vozvrat
{
  "kody": ["0104601234567890215Abc…\u001d93dGVz"],
  "otkloneno": [{ "kod": "0104601234567890215Abc…\u001d93dGVz", "prichina": "носили, нет ярлыка" }]
}
```

`kody` — коды пар, которые физически пришли, как отдаёт сканер. Если в
одной посылке и невыкуп, и возврат покупателя — шлите всё вместе, мы
разберём по кодам.

`otkloneno` — только для возврата покупателя: пары, которые принять
нельзя (носили, нет ярлыков, испорчены). Каждый `kod` должен быть и в
`kody`. Деньги за них не вернём, Тимофей свяжется с покупателем. Можно не
присылать.

Ответ:

```json
{
  "sostoyanie": "vozvrat_prinyat", "sovpalo": true, "ne_zhdali": [], "ne_prishli": [],
  "zayavki": [{ "nomer": "41-В1", "status": "prinyat", "vernuli": 8499, "otkloneno": [] }]
}
```

`zayavki` — что стало с заявками покупателя: `prinyat` — приняли всё и
вернули деньги, `chastichno` — часть отклонили, `otklonen` — не приняли
ничего.

`sovpalo: false` — пришло не то, что ждали: в `ne_zhdali` коды, которых
не ждали, в `ne_prishli` — те, что ждали, но не пришли. Ничего делать не
нужно, мы разберёмся сами. Повтор не ошибка — придёт `uzhe_prinyat`.

Остаток по вернувшимся парам — как обычно, следующей заливкой
`/sklad/ostatki`.
